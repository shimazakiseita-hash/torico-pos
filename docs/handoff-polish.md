# 引き継ぎ：お客さん向けページとミニゲームの仕上げ

焼き鳥屋台「やきとり TORI♡CO」（津田沼祭、2026年11月21日・22日）の、お客さんがスマホで見るページとミニゲームの完成度を上げてほしい。
このファイルだけ読めば作業を始められるように書いてある。細かい仕様は `docs/spec.md`、デザインの基準は `docs/design.md` にある。

## 締め切りと優先順位
- 本番は 11/21 の朝。**壊さないことが最優先**。大きな作り直しより、見た目・手ざわり・わかりやすさの磨き込みを優先する。
- 変更は小さく分けて、1つずつ動作確認する。

## 対象と対象外
| 範囲 | 場所 | 今回 |
|---|---|---|
| ミニゲーム（ハブ・ガチャ・きせかえ・ショップ・ランキング・2つのゲーム） | `cloud/public/game/` | **対象** |
| お客さんの呼び出し状況ページ（整理券のQRから開く） | `cloud/src/page.ts`（HTMLを返す）、`cloud/src/index.ts`（API） | 対象（見た目のみ。APIの形は変えない） |
| 店員の画面（会計・焼き場・渡し場・管理） | `src/`（Next.js） | **対象外**。当日の運用に直結するので触らない |

## 構成（お客さん側）
- Cloudflare Workers で配信。`cloud/public/` は静的ファイル、`cloud/src/index.ts` が API（呼び出し状況・ランキング）。ランキングは Durable Object。
- ミニゲームはフレームワークなしの素の JS（ES modules）＋ canvas。
  - `index.html` / `style.css`：画面（hub, dress, gacha, shop, play, result, rank, shot-map, shot-result）。`[hidden]` で切り替え。
  - `app.js`：画面遷移、ゲームループ、一時停止、結果、ランキング表示。
  - `common.js`：論理サイズ（W=360×H=640、`view` が実際に見えている範囲）、マスコット・串の描画、保存（localStorage `torico-game`）、ランキング通信、振動 `buzz()`。
  - `flight.js`：とりこフライト（タップではばたいて障害物を抜ける。アイテム、周回ごとのボス。ランキングあり）。
  - `shot.js`：とりこショット（引っぱって飛ばし砦を崩す物理パズル、Matter.js。全20面、20面はボス、★は残り玉、技4種、花火玉、ヒットストップ）。
  - `shop.js`：ガチャ・強化。
  - 各ゲームは `META` と `createGame()` を export し、`state / pointer(type,x,y) / update(dt) / draw(ctx)` を持つ。
- フォントは Zen Maru Gothic の**サブセット**（使っている文字だけ入れた woff2）。**新しい文字を画面に足したら `cd cloud && npm run assets` で作り直す**。忘れると文字が出ない。絵文字や記号（⏸ など）はフォントに無いので使わず、SVG か canvas で描く。

## 動かし方と確認
```bash
# Node は .nvmrc のバージョン（v24 系）
cd cloud && npm install
npx wrangler dev --port 8798      # http://localhost:8798/game/ がミニゲーム、/ が呼び出し状況
```
- スマホ幅（390×844 前後）で必ず確認する。PC幅で崩れないことも見る。
- `http://localhost:8798/game/?debug` だと `window.__game` からゲームの状態を触れる（localhost のみ）。
- 変更後に通すもの（リポジトリ直下で）：
  ```bash
  npm run lint && npm test
  cd cloud && npx tsc --noEmit
  node --check cloud/public/game/*.js
  ```

## 守ってほしいこと
- **ゲームのルール・点数・難易度・ステージ配置は変えない**。ランキングの不正判定（`src/lib/ranking.ts` の上限）とポイントの釣り合いが崩れる。変えたい場合は提案だけにする。
- **保存データの形を壊さない**。古い保存データ（localStorage）でも読めること。
- デザインは `docs/design.md` の「宇宙 × ゆめかわ」とカラートークンに合わせる。お客さん側は宇宙（濃い紫＋星）の世界。
- 文言は日本語、子どもも読めるようにひらがな多め。店名表記は「やきとり TORI♡CO」。
- **とりこショットのステージ画面の中に日本語の説明文を増やさない**（オーナーの方針。説明はスタート前のカードだけ、画面内は絵と動きで見せる）。
- 外部の CDN・Webフォント・画像サービスは使わない（必要なものは同梱する）。
- 秘密情報（`.env.public` など）は読まない・書かない・コミットしない。
- コメントは必要最低限、日本語で1行程度。関係ない箇所の書き方を変えない（差分を小さく）。
- **デプロイ（`npm run deploy`）と `git push` はしない**。変更内容と確認結果を報告して、オーナー側で公開する。

## 改善の候補（優先度の目安つき）
自由に提案してよい。下はこれまでに気づいている点。

**見た目・手ざわり**
- 効果音がまったく無い（高）。入れるなら、最初のタップで音を有効にする・音量控えめ・オン/オフ（振動の「ぶるぶる」トグルと同じ場所）を用意する。
- 画面遷移やボタンの押し心地のアニメーションが少ない（中）。
- 結果画面（フライトの点数、ショットの★）の盛り上げ演出（中）。
- ハブ（最初の画面）の情報が多く、初めての人が何を押せばいいか迷う（中）。

**ゲームごと**
- フライト：最初のボスに会うまでに40本抜ける必要があり、多くの人は会えない。1体目のボスは弱すぎる（HP 30）。→ ルール変更になるので提案のみ。
- ショット：11面・18面は狙っても★3（1発クリア）がほぼ取れない。→ 提案のみ。
- ショット：花火玉の爆発や技の演出は、もっと派手にしてよい（物理の結果は変えないこと）。

**お客さんの呼び出し状況ページ**
- 番号が呼ばれたときの見せ方（大きさ・色・動き）をもっと目立たせられる。
