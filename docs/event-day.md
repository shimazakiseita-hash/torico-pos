# 当日の運用手順 — やきとり TORI♡CO（11/21・11/22）

責任者がいなくても、この紙だけで開店準備と営業ができるように書いています。
※ 11/18 の実機リハーサルのあとで、実際の手順と違うところを直すこと。

## 持ち物
- [ ] PC 4台と、それぞれの電源（延長コード・電源タップ）。雨よけ・日よけ
- [ ] 整理券：1〜500番の束を **2つ**（1日目用・2日目用）。どちらも1番が上になるように重ねる
- [ ] 整理券のポスター（屋台に貼る。お客さんがQRで呼び出し状況を見られる）
- [ ] 釣り銭、コインケース
- [ ] 予備の紙：注文メモ用紙（串5種×たれ・塩の表）、ペン

## 前日までの準備（責任者）
- [ ] サーバーPCの準備が済んでいる（`docs/network.md`）。`.env.public` がサーバーPCにある
- [ ] 4台すべてで Wi-Fi「TORICO-POS」を保存し、上のアドレスをブックマーク。スリープ・画面オフを無効に
- [ ] 最新版に更新：`cd ~/torico-pos && git pull && npm ci && npm run build && sudo systemctl restart torico-pos`
- [ ] 練習で入れた注文を消す：`npm run db:reset`（確認が出るので yes）
- [ ] 管理画面で両日の「釣り銭準備金」を入れる（「1日目」「2日目」を選んで、レジ締めの欄で保存）
- [ ] 管理画面で販売上限を確認（初期値：もも500本、ほか250本。たれ・塩の合計）

## 開店手順（毎朝）
1. サーバーPC（受付）の電源を入れる。Wi-Fi親機とアプリは自動で起動する
2. 残り3台の電源を入れ、Wi-Fi「TORICO-POS」につながったらブックマークを開く
3. それぞれの画面を1回タップする（画面が消えない設定になる。下の黄色い帯が消えればOK）。呼び出し表示は F11 で全画面に
4. 管理画面を開き、次を確認する
   - 右上が今日（「1日目」または「2日目」）になっている
   - 「公開ページ（整理券のQR）」が緑で「最終更新 ○秒前」。赤なら下の「トラブル時」へ（営業はできる）
   - 釣り銭準備金が今日の金額になっている
5. 試しに1件：受付で注文 → 焼き場にカードが出る →「完成」→ 渡し場と呼び出し表示に番号が出る → スマホで1番の整理券のQRを読んで「できあがりました！」を確認
6. 片付け：焼き場の「○番を戻す」で焼き待ちに戻す → 受付の「直近の注文」から取り消す。**この1番の整理券は捨てる**（お客さんは2番から）

## 営業中
- **受付**：串のボタンで本数を入れる → 預かり金額を押す → お釣りを渡す → 「会計確定 → 番号発行」→ 画面の番号と同じ整理券を **束の上から** 渡す
  - 押し間違いは「−」か長押しで減らす。確定後の間違いは「直近の注文」から取り消して入れ直す（取り消した番号の整理券は捨てる）
- **焼き場**：右の「いま必要な本数」を見て焼く。味付け担当は古い注文（左上）から1件ぶんを仕上げて「完成」
  - 10分以上待っている注文は赤くなる。押し間違えたら下の「○番を戻す」
- **渡し場**：呼び出し中の番号を呼ぶ → 整理券の番号を確かめて渡す →「渡した」
  - 押し間違えたら右下の「受け渡し済み」から「戻す」
- **売り切れ**：上限の本数まで売れると、自動で受付のボタンが押せなくなる。たれ・塩などが先に切れたときは、責任者が管理画面の「販売上限と売り切れ」で「たれを売り切れに」などを押す（もう一度押すと戻る）
- **バックアップ**：サーバーPCが10分ごとに自動で取る。念のため、責任者は1時間ごとに管理画面からCSVをダウンロード
- **お客さんのスマホ**：整理券のQRから、自分の番号の状況・待ち時間のめやすが見られる。待っている間はミニゲームでも遊べる

## トラブル時

| 症状 | 対応 |
|---|---|
| 画面上部に赤い「接続エラー」 | その端末のWi-Fiが「TORICO-POS」につながっているか確認 → つなぎ直してページを再読み込み |
| 全部の端末が接続エラー | サーバーPCがスリープ・電源切れになっていないか確認。電源を入れ直せば自動で復旧する（データは残る） |
| サーバーPCは動いているのにつながらない | サーバーPCで `nmcli connection up torico-ap`、`sudo systemctl restart torico-pos` |
| Wi-Fiが不安定 | サーバーPCを店の中央・高い位置に置く。だめなら `docs/network.md` の代替案（ルーター／有線／テザリング） |
| 管理画面の「公開ページ」が赤い | サーバーPCのインターネット接続を確認（`docs/network.md` 6）。店内の画面は影響を受けないので営業は続ける。お客さんのスマホには「状況を確認できません」と出るので、店頭の呼び出し表示と声で案内する。つながれば自動で追いつく |
| どうしても復旧しない | **紙運用に切り替え**：番号は最後に発行した番号の続きから整理券を渡し、注文は紙の表に正の字で記録し、あとでまとめて入力 |

## 閉店後（毎日）
1. 管理画面の「レジ締め」で、レジ内の現金を数えて「数えた現金」に入れ、差額を確認（ぴったりなら緑）
2. 「CSV（全注文）」で今日の注文をダウンロードし、共有フォルダに保存
3. サーバーPCで `npm run closing -- on`（お客さんのスマホページを「本日の営業は終了しました」にする。ミニゲームはそのまま遊べる）
4. `data/torico.db` と `backups/` をUSBメモリなどにコピー
5. 4台の電源を切る。**DBの初期化はしない**（2日目は日付で自動的に切り替わり、番号は1から始まる）

## 2日目の朝
- 開店手順の前に、サーバーPCで `npm run closing -- off`（スマホページを番号の表示に戻す）
- 整理券は **2日目用の新しい束** を使う（1番から）

## 2日目の終了後
- 管理画面の「合計」で2日間の売上・本数を確認し、会計報告に使う
- サーバーPCのスリープ設定を元に戻す（`docs/network.md` 4）
- ミニゲームのランキングに不適切な名前があれば：`npm run ranking -- catch`（ゲームは tsumi・catch・flight）で ID を見て、`npm run ranking -- remove <ID>`
